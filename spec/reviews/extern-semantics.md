# `extern` semantics (proposal, spec 0.2)

Author: Picasso. Status: **proposal for 0.2**, not part of the 0.1 spec;
accepted for 0.2 with four rulings (`reviews/extern-review.md`), which are
folded in below. Verse 0.1 adds no syntax and no `extern` word (§18.15). The
readability constraints are Michelangelo's (`reviews/extern-readability.md`,
cited as C1–C7). The exact spelling is left to the 0.2 spec section; the
examples are not valid 0.1 Verse.

## 1. Words

- A **capability** is a kind of system access that a program or plugin needs,
  such as `fs`, `net` or `gpio`.
- To **grant** a capability is to give it: in `verse.toml`, or by not denying
  it with `verse run --deny <capability>`.

No other words are used for this idea.

## 2. What `extern` is for

Calling foreign code of two kinds, under the same rules:

1. **Native libraries** through the C ABI: system libraries on embedded
   targets, numeric libraries for the `ml` package, and code generated by
   `bindgen` plugins (architecture 07).
2. **WebAssembly component imports** (architecture 07 library plugins).

Not included: foreign types with methods, and callbacks from foreign code into
Verse.

## 3. Rules

| # | Rule | Constraint |
|---|------|------------|
| E1 | **Declared through the import form.** Foreign functions are imported from a named library or component, after `from`, like any other import. A native library is listed in `[library.native]` (§16.3), which is data: building still runs no code. | C1 |
| E2 | **Signature always written.** Every parameter and the return type are annotated, and so are ownership words (`take`, `mut`, or a plain borrow). Nothing is inferred across the boundary, and the signature goes into `verse.api`. | C2 |
| E3 | **Callable only inside a matching `with` block, through its bound name.** Each foreign library declares the capability it needs. A call compiles only inside a `with` block that binds a value holding that capability (the resource form of §13), and **the bound name must appear in the calls it permits**: it is passed to the call, for example as the first argument. Elsewhere the call is a compile error that names the capability and shows the line to add: "calling `write_pin` needs the `gpio` capability; wrap the call in `with gpio() as …`". | C3 |
| E4 | **Pure libraries need no `with`.** A library marked `pure = true` in `[library.native]` needs no capability, so its functions are called like any others, without a `with` block (a `libm` call such as `sqrt(x)`). | C3 |
| E5 | **The call looks like a normal call.** No `unsafe` marker and no casts; the `with` block and its bound name are the one visible sign that foreign code with a capability runs there. | C3 |
| E6 | **Plain data only.** Allowed across the boundary: `Int`, `Float`, `Bool`, the sized numeric types of `std.num`, `Bytes` and byte views (§4.1), and records made only of these (`Copy` records, §4.9). Not allowed: collections, optionals, variants, trait types, closures, `Task`, `Cleanup` types, and **`Text`**: write `text.bytes()`, the one spelling, which keeps the conversion visible. A violation is a compile error that names the type and lists the allowed ones. | C5 |
| E7 | **Fallible by type.** A foreign function that can fail is declared as returning `T \| Error`; the binding turns status codes into error values, and the caller handles them with `?`, `otherwise` or `match`, as for any other call (§8). | C4 |
| E8 | **Ownership at the boundary.** A borrowed argument is valid only for the call; foreign code may not keep it. A `take` argument is handed over and is not cleaned up by Verse. A returned value is owned by the caller. | C2, C7 |
| E9 | **Each call site is a capability use.** For reachability (architecture 06 §6.4, ADR-0004), every reachable call site adds an `extern` edge to the capability's runtime slice and to the native library or component. An unreachable foreign import links nothing and needs no capability. `verse run --deny <capability>` and `verse check --target <T>` (§16) report such calls before the program starts. | — |
| E10 | **Generated bindings are ordinary files.** `bindgen` output lives in `generated/` with a header comment, and all normal rules apply. | C6 |
| E11 | **Debugger.** A foreign call shows as `called` with `foreign: true`; its inside is not stepped. A value that crossed the boundary shows `state: owned` with the note `from_foreign`, worded "came from a foreign call". The note needs an entry in `vocab/events.toml` (owned by Michelangelo, architecture 08 §8.7) before it can be emitted. | C7 |
| E12 | **Script mode.** The bytecode VM (tier 0) calls the same functions through the same checks, so a program means the same thing in both modes. A target without native linking (browser WebAssembly) rejects native imports at `verse check --target`. | — |

## 4. Shape to evaluate (0.2, not valid 0.1)

```
import write_pin from c "board"      # C1 shape; `board` declares the gpio capability
import sqrt from c "libm"            # `libm` is marked pure

with gpio()? as pins                 # E3: binds a value holding the gpio capability
    write_pin(pins, 13, true)?       # E3: the bound name appears in the call; E7: fallible

root = sqrt(2.0)                     # E4: pure, no `with` block
```

`gpio()` is a placeholder for the 0.2 spelling of the resource that holds the
capability; it is not a proposed `std` name.

```toml
[library.native]
links = ["m"]
pure  = true                         # E4: no capability needed
```

## 5. Rulings folded in (`reviews/extern-review.md`)

| Open point | Ruling | Where |
|------------|--------|-------|
| 1. How a `with` block holds a capability | Existing resource form; the bound name must appear in the calls it permits | E3, §4 |
| 2. Pure libraries | `pure` marker in `[library.native]`; no `with` | E4, §4 |
| 3. `Text` across the boundary | No; `text.bytes()` is the one spelling | E6 |
| 4. Wasm component imports | Second foreign kind, same rules | §2, E1, E9 |

Remaining for the 0.2 spec section: the exact spelling of foreign imports and
of the capability resource, and the `vocab/events.toml` entry for
`from_foreign` (Michelangelo).
