# `extern` semantics (proposal, spec 0.2)

Author: Picasso. Status: **proposal for 0.2**, not part of the 0.1 spec.
Verse 0.1 adds no syntax and no `extern` word (§18.15). The readability
constraints are Michelangelo's (`reviews/extern-readability.md`, cited
below as C1–C7). The exact spelling is left to the 0.2 spec section; the
examples use the shape C1 asks to evaluate and are not valid 0.1 Verse.

## 1. What `extern` is for

Calling functions in native libraries through the C ABI: system libraries
on embedded targets, numeric libraries for the `ml` package, and code
generated by `bindgen` plugins (architecture 07). Nothing else: no foreign
types with methods, no callbacks from foreign code into Verse in 0.2.

## 2. Rules

| # | Rule | Constraint |
|---|------|------------|
| E1 | **Declared through the import form.** Foreign functions are imported from a named library, after `from`, like any other import. The library is listed in `[library.native]` (§16.3), which is data: building still runs no code. | C1 |
| E2 | **Signature always written.** Every parameter and the return type are annotated, and so are ownership words (`take`, `mut`, or a plain borrow). Nothing is inferred across the boundary, and the signature goes into `verse.api`. | C2 |
| E3 | **Callable only inside a matching `with` block.** Each foreign library declares the system capability it needs (for example `fs`, `net`, `gpio`). A call compiles only inside a `with` block that holds that capability; elsewhere it is a compile error that names the capability and shows the `with` line to add. | C3 |
| E4 | **The call looks like a normal call.** No `unsafe` marker and no casts; the `with` block is the one visible sign that foreign code runs there. | C3 |
| E5 | **Plain data only.** Allowed across the boundary: `Int`, `Float`, `Bool`, the sized numeric types of `std.num`, `Bytes` and byte views (§4.1), and records made only of these (`Copy` records, §4.9). Not allowed: `Text` (pass `text.bytes()`), collections, optionals, variants, trait types, closures, `Task`, and `Cleanup` types. A violation is a compile error that names the type and lists the allowed ones. | C5 |
| E6 | **Fallible by type.** A foreign function that can fail is declared as returning `T \| Error`; the binding turns status codes into error values, and the caller handles them with `?`, `otherwise` or `match`, as for any other call (§8). | C4 |
| E7 | **Ownership at the boundary.** A borrowed argument is valid only for the call; foreign code may not keep it. A `take` argument is handed over and is not cleaned up by Verse. A returned value is owned by the caller. | C2, C7 |
| E8 | **Each call site is a capability use.** For reachability (architecture 06 §6.4, ADR-0004), every reachable call site adds an `extern` edge to the capability's runtime slice and to the native library. An unreachable `extern` import links nothing and needs no capability. `verse run --deny <capability>` and `verse check --target <T>` (§16) report such calls before the program starts. | — |
| E9 | **Generated bindings are ordinary files.** `bindgen` output lives in `generated/` with a header comment, and all normal rules apply. | C6 |
| E10 | **Debugger.** A foreign call shows as `called` with `foreign: true`; its inside is not stepped. A value that crossed the boundary shows `state: owned` with a `from_foreign` note. | C7 |
| E11 | **Script mode.** The bytecode VM (tier 0) calls the same functions through the same checks, so a program means the same thing in both modes. A target without native linking (browser WebAssembly) rejects `extern` imports at `verse check --target`. | — |

## 3. Shape to evaluate (0.2, not valid 0.1)

```
import write_pin from c "board"      # C1 shape; spelling open. `board` declares capability gpio

with gpio()? as pins                 # E3: the block holds the gpio capability
    write_pin(13, true)?             # E4: an ordinary call; E6: fallible by type
```

`gpio()` is a placeholder for however a block comes to hold a capability
(open point 1); it is not a proposed `std` name.

## 4. Open points for the 0.2 ruling

1. How a `with` block "holds" a capability: a capability value from `std`
   (as sketched above) or the existing resource (for example an open `File`
   for `fs`). The first is simpler; the second adds no new values.
2. Whether a library that needs no capability (pure math, as `libm`) may be
   called outside `with`. E3 as written says no; a `pure` marker in
   `[library.native]` would allow it.
3. Whether `Text` may cross as read-only UTF-8 with a length (rather than
   only through `text.bytes()`).
4. Wasm component imports (architecture 07 library plugins) as a second
   foreign kind, with the same rules.
